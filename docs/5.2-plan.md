## 二、技术路线与原则

- **复用不重写**：治理库 `governance_store`、周期 `healthcycle`、差距 `arch_gap_analyzer`、
  任务卡 `refactor_task_generator`、对齐 `arch_alignment_verifier`、画布 `canvas_generator`。
- **确定性优先**：新能力一律静态可复现；探针只做"静态层动态信号挖掘"，不实际执行业务代码。
- **Web 形态务实化**：延续项目惯例（自包含离线 HTML，零 CDN），看板 = 自包含交互 HTML +
  标准库 `http.server` 只读服务（不引入 FastAPI/前端工程化），完整应用态为后续形态。
- **定时不内置**：延续 5.1 决策（MCP 无常驻定时），只产出外部 cron/CI 触发片段。

## 三、各模块设计

### 3.1 治理自动化连接线 `core/gov_pipeline.py`

把"工作项治理 → 生成任务卡 → 执行反馈 → 复验 → 归档"串成一条可追踪流水线。

- `run_pipeline(issue_ids, changed_files)`: pipeline **只负责任编与复验，不执行修复**
  （执行修复交给编程 AI）。合法输入仅为状态机的在途项 **Confirmed / Fixing**；
  **Detected 项不接收**——Detected 必须先经确认流转为 Confirmed 后才能进入流水线
  （状态机 Detected → 仅 Confirmed / Rejected），否则会被拒绝并返回"无法进入 Fixing"。
  对每个在途项：
  1. 状态 → Fixing（若为 Confirmed）
  2. 调 `refactor_task_generator` 生成任务卡（含影响范围/验证标准）
  3. 以 `changed_files`（本次已执行改动的文件集合）作为**执行反馈**输入，调
     `arch_alignment_verifier`（增量复验，缺省全量）复验——反馈即复验依据；
     无反馈且差异仍复现则维持 Fixing 附缺口，绝不无凭据进 Verified
  4. 复验达标（该差距不再复现）→ Verified；否则保持 Fixing 并附缺口
- 每步 `store.transition` 的返回值被检查；流转被状态机拒绝（如 Detected→Fixing）时，
  该工作项标记失败并返回明确 message，不虚假上报 Fixing/Verified。
- 全程写 `issue_event`。
- MCP：`coderef_gov_pipeline`。

### 3.2 动态探针 Phase 3 `core/dynamic_probe.py`

补全静态盲区——挖掘"静态 AST 看不到、运行时才成立"的动态信号，但**不执行被检项目代码**：
- 动态导入：`importlib.import_module` / `__import__` / `pkgutil` 的参数字面量 → 补调用边
- 延迟绑定 / 工具注册：装饰器注册（`@app.route`、`registry.register` 等含可解析目标）
- 工厂 / 回调登记：把字面量字符串作为符号名经 `getattr`/`globals()` 索引 → 补 CONTAINS 边
- 配置驱动的组件发现：从 `setuptools` entry_points / 配置清单里的模块路径 → 补模块节点
- 输出：`probe_edges`（新增调用/CONTAINS 边）+ `probe_hints`（动态但无法静态解析的候选，
  标注程度 uncertainty），允许并入图谱或单独一份 JSON 供人工核对。
- 危险操作隔离：默认零执行；不 import、不 subprocess 被检项目。
- MCP：`coderef_dynamic_probe`。

### 3.3 治理 Web 看板 `core/gov_webdash.py`

- `render_board(project_path, ...) → HTML`：自包含交互单页，含
  顶部 KPI（完成率/复发/剩余）、状态分布、按角色/模块分布、跨期趋势折线、工作项表格
  （按预置视图筛选、状态流转）、周期选择。
- `serve(project_path, host, port)`：`http.server` 服务，暴露看板 HTML +
  `/api/report`、`/api/issues`、`/api/cycles` **只读** JSON；配合 3.7 应用态时另有
  `/api/issue/<id>`（详情）与 **`POST /api/transition`（写回治理库，限 127.0.0.1）**。
  **统一读写契约**：全部 `/api/*` 端点仅允许本机回环访问（读取同样受限），且绑定
  host 被强制为 127.0.0.1/::1/localhost，防止治理数据（模块路径、负责人）暴露到局域网；
  数据回写仅 `POST /api/transition` 一个入口，与 `coderef_gov_transition` 同语义。
- 复用 `gov_dashboard` 报告聚合 + `gov_view` 视图。
- MCP：`coderef_gov_board`（生成 HTML，可带 `open` 起本地服务）。

### 3.4 多代码库聚合 + 定时调度

`core/gov_workspace.py`：
- `workspace` = 一组 project 的聚合治理边界（对应 plane Workspace）。
- `aggregate(projects) → report`：跨仓汇总 open/high/复发/趋势，给出跨仓 TOP 风险。
- `add_member`/`list` 走 governance_store 扩展表（`gov_setting` 存 workspace 清单）。
- MCP：`coderef_gov_workspace`。

`core/gov_schedule.py`：
- `render(cycles, cron_expr) → dict`：一个 cron/CI 触发模板片段 + 用法说明 + 空跑检查
  （周期含 `end_date` && status=open 已过期 → 提示"离期未复检"）。
- 不内置后台定时（延续决策）。
- MCP：`coderef_gov_schedule`。

### 3.5 5.0 遗留增强

- **对齐度健康维度**（`arch_gap_analyzer` / `arch_alignment_verifier`）：
  缺 arch_audit 健康度时，从图谱实算"模块规模分布 + 扇出/扇入超阈值比例 + 环存在"，替代固定 0.5 兜底。
- **任务卡 true 依赖拓扑**（`refactor_task_generator`）：
  从图谱模块依赖边推导任务卡间依赖（若 A 依赖 B 且都需改动，A 排在 B 后），替代纯类型级启发式。

### 3.6 符号级职责越界检测 `core/role_boundary.py`（本轮升格实现）

解决 5.0 §6.2 遗留：模块归属正确，但模块内的**符号职责**逾越了它所属角色的边界
（如 `waiter.py` 里定义/调用了本属 `cook()` 的职责）。

- **静态层职责信号**（确定性，零 LLM）：对每个模块做 AST 分析，把模块内顶层函数/类/方法
  归类为"本角色职责"与"疑似越界职责"：
  - 命名语义：符号名与 `tech_roles.role_keywords`（角色职责关键词表）匹配 → 判定该符号属于某角色。
  - 调用边界：模块调用图谱里，若本角色模块 A 调用了属于角色 X（X≠本角色）的符号/入口，标记"跨角色调用"。
  - 复用信号：某个符号在目标架构其他角色的 target_modules 中作为核心符号存在，却定义在本模块 → 越界候选。
- **语义判定接口**（可选，缺 LLM 时只给静态信号 + 标注 uncertainty，不硬阻断）：调用存在时
  对 top 候选做语义确认，返回"越界/可接受"及理由。
- **输出**：`boundary_issues`（symbol / 所在模块 / 所属角色 / 疑似归属角色 / signals / uncertainty），
  确定性字段（symbol 定位、匹配到的关键词、调用证据）不依赖 LLM；`semantic_note` 可选。
- **定位方式**：基于已有知识图谱（function/class/method + CALLS/CONTAINS 边）+ 目标架构 role_keywords。
- MCP：`coderef_role_boundary`。

### 3.7 Web 看板应用态增强 `core/gov_webdash.py`（续 3.3）

在"自包含 HTML + `http.server` 只读服务"基础上，把看板推进到**可交互应用态**：

- **交互能力**：工作项表格支持按预置视图/状态/角色筛选、点击行展开详情（证据/活动日志）、
  状态流转按钮（Detected→Confirmed→Fixing→Verified，写回治理库）、周期下拉切换。
- **数据回写**：`/api/transition` POST 端点（限 127.0.0.1）把前端流转写回 `governance_store`，
  与 `coderef_gov_transition` 同语义。
- **形态务实**：仍为单文件自包含 HTML + 标准库 `http.server`（不引入 FastAPI/React 工程化），
  但前端 JS 由"只看"升级为"可操作"。
- MCP：`coderef_gov_board` 增加 `interactive=True` 开关（默认开）。

### 3.8 定时体检实跑落地 `core/gov_schedule.py`（续 3.4）

从"产出 cron/CI 片段"升级为**真实可触发的调度入口**：

- **可执行触发脚本**：`render` 除返回 cron 片段外，额外生成一个可直接运行的入口脚本
  `run_cycle.py`（调用 `HealthCycle.start_cycle` 开新周期 + 导入差距 + 产出报告 JSON/HTML），
  供 cron/CI/人工直接 `python run_cycle.py --project <path> --name <cycle>` 调用。
- **离期检查可调度**：`render` 输出一个"体检 + 离期提醒"的完整 shell/powershell 触发命令，
  已验证可被 cron/CI 消费（空跑检查 `--check` 仅报告不建档）。
- **不内置后台驻留**（延续决策）：触发交给外层 cron/CI/任务计划，CodeRef 提供已验证的入口。
- MCP：`coderef_gov_schedule` 返回 `runnable_script` 路径 + 触发命令。

## 五、验证方案

- **pipeline**：对 requests 若干 Confirmed/Fixing 在途项跑 `coderef_gov_pipeline`，观察状态链 + verify 达标/未达标分支；Detected 项应被拒绝（无法进入 Fixing）。
- **probe**：requests 上挖掘动态信号，断言零执行（不新增 import 副作用）、输出边可并入图谱。
- **webdash**：生成自包含 HTML 打开无报错；`serve` 起服务后 `/api/report` `/api/issues` `/api/cycles` 返回 200；
  `interactive=True` 时 `/api/transition` 回写治理库（仅 127.0.0.1）。
- **workspace**：两仓（requests + 自建小样本）聚合，跨仓统计正确。
- **schedule**：含过期 open 周期时触发"离期提醒"；`run_cycle.py --check` 仅报告不建档。
- **legacy**：无 arch_audit 健康度时对齐度仍合理（0~1）。
- **role_boundary**：构造 waiter.py 含 cook() 的样本，断言静态信号能定位越界 symbol；LLM 语义接口不可用时只出静态信号不硬阻断。
