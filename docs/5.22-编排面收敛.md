# 5.22 编排面收敛（提案 · 未实施）

> 状态：提案，仅记录，不改代码与 Skill 结构。提出日期 2026-11-10；当前基线 5.21.12。
> 触发：梦系统（5.20–5.21）已承担跨会话记忆与开工建议，L1/L2/L3 三层入口叙事与梦的 `routing` / `triage`、dispatcher 意图选择出现重叠。

## 1. 现状

- `core/dispatch_chains.yaml` 已有 6 条链：`probe` / `single_audit` / `recover` / `remind` / `governance` / `asset`；L1/L2/L3 只对应其中 3 条。
- 公开面有 5 份 Skill：`coderef-mcp` / `coderef-probe` / `coderef-governance` / `coderef-governance-semi` / `coderef-asset`，每份都带「意图 → 工具」路由。
- 梦提供 `routing`（当 X 先用 Y）、`triage`（先看什么）、`recap`，并通过 `memory_digest` 注入；与 `coderef-mcp` 的「顶层入口判定」、dispatcher 的意图选择重叠。
- README 用 L1/L2/L3 编号组织 59 个工具，外部用户需要先理解三层编号才能选链。

## 2. 判断

- **不简化执行骨架**：L1（增量变更守卫）与 L2（存量结构治理）的风险模型不同；YAML 单一事实源、precondition 闸门、编排 gate 是安全边界。
- **简化入口叙事**：L3 本质是治理收尾分支，不应与 L1/L2 并列成链；软门禁版治理是同一主链的确认策略，不应单独成 Skill；重复路由表应收敛到一处。
- **梦的定位**：只提供建议（写进 `memory_digest` / `triage`），不替代确定性意图选择；冲突时以 `coderef_plan` 的意图枚举为准。

## 3. 目标形态

两模式 + 一分支：

| 模式 | 对应现状 | 典型触发 |
|---|---|---|
| 日常变更 | L1 `probe` | 每次改码、提交前、CI |
| 存量治理 | L2 `governance`（含 semi 确认策略） | 重复/孪生/模块归属混乱、周期体检 |
| 资产沉淀 | L3 `asset`（治理收尾分支） | 治理后发现可复用设计、复刻到新项目 |

Skill 收敛：

| 现状 | 目标 |
|---|---|
| `coderef-mcp` | 保留：入口判定 + 梦协议 + 工具速查 |
| `coderef-probe` | 收敛为 `coderef-change`（模式 A） |
| `coderef-governance` + `coderef-governance-semi` | 合并为 `coderef-governance`，软门禁作为其中一节 |
| `coderef-asset` | 降为治理文档的「资产收尾」附录，或保留短文档但不再称 L3 |

YAML：

- 步骤不变；仅考虑把 `asset` 从独立 chain 改为 `governance` 后置分支（可选，需确认 dispatcher 是否支持 branch；不支持则保留 chain，只改对外命名）。

## 4. 不做什么

- 不删减 59 个工具，不改审计/图谱/架构/流程/守卫/OWASP 的确定性实现。
- 不删 gate、precondition、freshness、envelope。
- 不让梦的 `routing` 直接触发执行，不新增 LLM 路由层。
- 不为旧称维护第二套 Skill，只在文档加「旧称对照」。

## 5. 旧称对照（拟）

| 旧称 | 新称 |
|---|---|
| L1 / `coderef-probe` | 日常变更模式 / `coderef-change` |
| L2 / `coderef-governance`（含 semi） | 存量治理模式 / `coderef-governance` |
| L3 / `coderef-asset` | 资产沉淀分支 / `coderef-asset`（工具组保留） |

## 6. 验收标准

1. Skill 文件 5 → 3；顶层路由只剩两个模式 + 一个可选分支。
2. `dispatch_chains.yaml` 的 `probe` / `governance` 步骤与失败策略不变；`asset` 如改分支，行为与现有 chain 等价。
3. 所有 gate / precondition 行为不变；STRICT 用例全绿；pytest 全绿；pyflakes 0；`check_version` EXIT=0。
4. 新增测试：梦 `routing` / `triage` 建议与 `coderef_plan` 意图冲突时，执行以 plan 为准。
5. README / Skill 只保留一张意图 → 工具主表；旧称对照可查。

## 7. 风险

- 外部用户已按 L1/L2/L3 写提示词：靠旧称对照与一版迁移说明缓解。
- Skill 合并可能让长文档更难读：用分节 + 场景卡控制篇幅。
- 资产分支若 dispatcher 不支持 branch，需新增 branch 语义：先评估，不强行改。

## 8. 结论

记入 5.22 候选，本轮不实施。实施前先确认两件事：

1. `asset` 是否改分支；
2. `coderef-change` 是否更名，或保留 `coderef-probe` 名称只改叙事。
