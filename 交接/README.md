## 双册对账机制（监控双册，各写各的）

- **测试侧登记册**：`测试归档\课题台账\登记册.md` —— 测试唯一写：发起课题（U-*）、写期望、回归验证、判定关闭。
- **开发侧响应册**：本目录 `响应册.md` —— 开发方唯一写：承接课题、修复版本号、回报结果与证据指针。
- **对账流程**：
  1. 测试在登记册登记新课题（写清期望）。
  2. 开发方读登记册 → 在本**响应册**回报承接与修复版本；同时升 `__init__.py`/README 末位版本、同步 `Coderef-Test\coderef-src`、重启 MCP（否则测试连旧进程误判）。
  3. 测试按新版本回归 → 通过后测试在登记册标记关闭并移入 `已关闭\`。
- **铁律**：任何一份报告只允许一个 owner 写。你只在响应册动，测试只在登记册动，不共写同一文件。
